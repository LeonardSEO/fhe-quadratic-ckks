# Focused primary-source comparison

Checked 2026-10-19. This is a bounded contribution comparison, not a proof of historical priority. None of the other systems' benchmark suites was reproduced for this release. Their timing claims remain author claims. The release compares explicit kernels in one pinned backend, rather than claiming to outperform whole compiler systems.

## Mechanism and closest comparators

The pass chooses a representative of a *scalar polynomial*: `A + transpose(A) = 2Q`. It does not preserve the intermediate vector `Qx`. Cyclic orientation combines opposite offsets before standard linear-transform lowering. Its restricted support theorem concerns representatives of this form; it says nothing about global ciphertext-circuit optimality.

| Comparator | What it preserves/optimizes | Precise distinction and obligation |
|---|---|---|
| Fused symmetric quadratic | The score `sum_i x_i (Qx)_i` using existing diagonal/BSGS kernels | Essential ablation: folding the network alone is not the proposed orientation rule. Compare tuned symmetric and oriented lowering. |
| Ordinary triangular symmetry elimination | The same scalar by retaining one entry of each unordered off-diagonal pair and doubling it | Elementary identity, no novelty claim. A dense triangular matrix can still occupy every cyclic diagonal; orienting whole offset pairs produces the stated support bound. Triangular is an implemented comparator. |
| Halevi–Shoup | A supplied linear transformation, using diagonal decomposition, BSGS, key-switching and hoisting choices | The release reuses these kernels. It changes the input matrix under terminal-scalar semantics first. Sparse support does not guarantee faster BSGS. |
| Coyote | Vectorized arithmetic-circuit schedules and lane assignment with rotation cost | Joint vectorization/layout optimization already exists. The candidate contribution is a specific scalar-equivalence rewrite before lowering, not general rotation minimization. |
| Fhelipe | Tensor-program semantics under automatic packing, layout conversion and bootstrap planning | Layout flexibility already exists. This release does not provide an end-to-end Fhelipe comparison or general packing discovery. |
| HECO | High-level imperative program semantics through layered SIMD transformations | Compiler restructuring and automated batching are prior work. Scalar-versus-unvectorized comparisons would be inadequate. |
| Orion | Neural inference through convolution packing, scale management and bootstrap placement | Infrastructure and optimized inference are prior work. Its network benchmarks differ from these terminal quadratic scores. |
| HEIR | HE-specific MLIR layers integrating optimization techniques and backends | A general integration framework already exists. This prototype is a standalone prepass, not a demonstrated HEIR integration. |
| Q-gym | Equivalent arithmetic expressions exploiting repeated quantized weights | Equivalent-expression search for encrypted inference predates this work. The proposed pass uses a closed-form scalar-quadratic representative rule, without claiming general consumer/equality optimization is new. |
| nGraph-HE2 | CKKS neural graph optimizations, including complex packing and rescale scheduling | Those mechanisms are prior art. Its client-aided native activations are outside this release's no-intermediate-decryption threat model. |
| KeyMemRT | Rotation-key lifetime management in an existing instruction stream | Key elimination by changing a computation is a different mechanism from loading/clearing an unchanged key set. Runtime liveness management is not claimed here. |
| FHE-Agent | Tool-guided Orion configuration using an LLM controller | This release specifies a deterministic construction and measured plan objective. It does not claim LLM configuration search as a method. |

The scalar identity, skew-symmetric freedom, ordinary symmetry elimination, diagonal kernels, BSGS and hoisting are established mathematics/techniques. The supported candidate contribution is the particular cyclic representative pass, its general restricted support proof, its checked implementation correspondence, and the measured deployment tradeoffs obtained before existing CKKS lowering. Priority for that precise combination remains unestablished.

## Search boundary

Focused primary-source queries included `quadratic form homomorphic CKKS optimization`, `quadratic upper triangular homomorphic`, `quadratic form cyclic diagonal encryption`, `homomorphic skew-symmetric`, and `equality saturation homomorphic encryption compiler`, plus the named systems. The search found quadratic optimization/gradient-descent applications whose iterates require matrix-vector information, and compiler/vectorization systems with different optimization abstractions. It did not establish whether the exact terminal-scalar offset-orientation rule appeared elsewhere. No absence-of-search-result argument is used for originality.

The paper should say “we study/implement/evaluate this pass” or “the candidate contribution is ...”, avoiding “first”, “new identity”, and “globally optimal FHE circuit”. The support theorem can be called optimal only with its explicitly stated density and representation assumptions.
