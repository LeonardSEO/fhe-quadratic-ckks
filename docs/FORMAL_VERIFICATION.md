# Formal verification boundary

The Lean project formalizes the exact real algebra and cyclic support statements. It does not formalize the Go evaluator, CKKS encryption, cryptographic security, hardware timings, or uniform numerical noise bounds. The executable exact-rational correspondence checks are a separate implementation bridge, not a formal verification of the entire compiler.

## Definitions and quantifiers

Every main theorem quantifies over an arbitrary natural dimension `n` with `[NeZero n]`, and arbitrary real matrices indexed by `ZMod n`. Thus the proofs include dimension one and every odd and even positive dimension.

`quadratic A x` is the finite double sum `sum_i sum_j x_i A_ij x_j`. `Admissible Q A` means entrywise `A_ij + A_ji = 2 Q_ij`. `Symmetric Q` means entrywise symmetry. `activeOffsets A` contains exactly the offsets `r` for which some `A_i,(i+r)` is nonzero. `CyclicDense Q` means every cyclic diagonal contains at least one nonzero coefficient. It does not require every individual matrix entry to be nonzero.

`orientation Q` retains `2 Q_ij` when the integer value of `j-i` is less than that of `i-j`; it retains `Q_ij` when the two values are equal; otherwise it uses zero. Equal values include offset zero and, for even dimensions, the half-turn offset. `canonicalOffsets n` selects offsets `r` satisfying `r.val <= (-r).val`.

## Exact declaration mapping

| Paper statement | Lean declaration in namespace `FHEQuadratic` |
|---|---|
| Scalar preservation for any admissible representative | `quadratic_preservation` |
| Orientation satisfies the entrywise representative equation for symmetric Q | `orientation_admissible` |
| Exact scalar preservation by the construction | `orientation_preservation` |
| Unchanged linear term and constant preserve the complete score | `affine_score_preservation` |
| Canonical offsets are the integers zero through floor(n/2) | `canonical_iff_val_le_half` |
| Exact number of canonical offsets | `canonicalOffsets_card` |
| Universal orientation support upper bound floor(n/2)+1 | `orientation_support_upper_bound` |
| Every dense admissible representative uses at least floor(n/2)+1 offsets | `activeOffsets_card_lower_bound` |
| The construction attains that exact cardinality under symmetry and density | `orientation_support_exact` |
| Restricted support optimum over admissible matrix representatives | `orientation_support_optimal` |

`quadratic_transpose`, `orientation_active_subset`, `canonicalOffsets_neg_unique`, `active_or_neg_active`, and `canonicalOffsets_card_le_activeOffsets_card` expose intermediate proof steps. The lower bound follows from density forcing at least one active offset in each sign orbit; the orbit-count hypothesis is not assumed.

The support theorem concerns the matrix-representative class, and does not assert globally optimal CKKS circuits or runtime. A sparse Q may admit smaller support. A different scalar computation or packing strategy may have a different optimum.

## Build and trust record

The integrated `lake build` succeeded on 2026-10-19 (1170 jobs). `python3 check_axioms.py` also succeeded, inspecting all eleven principal declarations. Every printed dependency set was exactly `[propext, Classical.choice, Quot.sound]`. An independent source audit and fresh project-object rebuild are recorded separately in `docs/LEAN_AUDIT.md` and `lean/evidence/independent_*`.

Initial proof compilation exposed two elaboration issues: an unqualified transpose rewrite matched the wrong scalar expression, and broad simplification expanded a support predicate inside a conditional. Explicit theorem arguments and restricted simplification repaired these issues without changing theorem statements or mathematical assumptions.

The trust boundary is Lean's kernel with standard logical axioms (`propext`, `Classical.choice`, and `Quot.sound`). The project introduces no additional mathematical axioms and uses no kernel-bypass mechanism. Principal theorem dependency output is generated by `FHEQuadratic/Axioms.lean`; the checker confirms that the released principal targets contain no `sorryAx` dependency.
