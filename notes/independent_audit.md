# Independent audit of the encrypted quadratic candidate

Audited 19 October 2026 in fresh agent context. Implementation was inspected, not edited. This audit covers `bench/packed.go`, `bench/main.go`, `compiler_ldl.py`, `generate_models.py`, `PROTOCOL.md`, the algebra/security/prior-art notes, the frozen model and validation JSON, and final Standard/CI aggregates available at audit time. No independent encrypted rerun was started because the main investigation was already measuring on the same machine; concurrent execution would contaminate timings.

## Verdict and exact scope

**Proof established in the checked scope:** for a public real symmetric Q, real x, and an observable terminal scalar `x^T Q x + l^T x + c`, the cyclic orientation construction preserves the exact polynomial. For a generic dense d-by-d Q it minimizes cyclic-diagonal support among representatives A satisfying `A+A^T=2Q`. It is not an optimum over FHE circuits, rotation schedules, ciphertext layouts, or complex factorizations. The executable supports power-of-two d>=2 dividing the available slots, with periodic replication and a valid interleaved batch.

The inspected implementation performs actual Lattigo CKKS encryption/evaluation/final decryption. No hidden intermediate decryption, client nonlinear evaluation, model-dependent client feature transformation, or plaintext substitution was found. Its experiments establish a controlled symmetric-versus-oriented contraction ablation. They do **not** establish superiority to the strongest available quadratic FHE implementation or publication priority.

## Independent algebra reconstruction

Write `A=Q+K`, `K^T=-K`. Since a real scalar equals its transpose, `x^T Kx = x^T K^T x = -x^T Kx`, and hence `x^T Ax=x^T Qx`. Equivalently, inspect each unordered pair: its contribution is `(A_ij+A_ji)x_i x_j=2Q_ij x_i x_j`; a diagonal contributes `A_ii x_i^2=Q_ii x_i^2`.

For cyclic distance r=(j-i) mod d, the code keeps Q at r=0 and r=d/2, keeps 2Q at 0<r<d/2, and sets larger distances to zero (`packed.go:219-235`). In a non-self-inverse pair {r,d-r}, precisely one direction remains doubled. For the self-inverse even half distance both ordered entries remain unchanged. Thus the symmetrization is exact. Adding l before multiplication gives `sum_i x_i((Ax)_i+l_i)+c`, exactly the required affine polynomial (`packed.go:59-72`). This rewrite would be wrong if an application also required Ax=Qx or exposed the intermediate vector.

For every nonzero cyclic-distance orbit of a generic dense Q, at least one partner diagonal of A must be active: otherwise the corresponding entries of sym(A) vanish. Offset zero and the even half offset require themselves. The resulting lower bound is `floor(d/2)+1` active diagonals; the construction attains it. For sparse Q, count only actually nonzero orbits; the generic bound need not be tight or applicable.

The interleaved input is `slot s = x[b][i]` with b=s mod B and i=floor(s/B) mod d. A rotation by rB replaces i by i+r while retaining b. The check `S%(dB)==0` ensures that this remains true across the physical slot boundary (`packed.go:120-125,305-307`). After the component product, the butterfly rotations B,2B,...,(d/2)B include each feature exactly once at every lane, because d is a power of two. Periodic replication repeats examples; it does not increase the count of independent examples.

Independently using Python integers and Fraction, I reconstructed each of the seven frozen networks' Q, l and c from W, v, bias, output bias and the exact dyadic normalization, then compared every stored binary64 coefficient as an exact rational. All passed. Each oriented A also passed the exact entrywise equality `A_ij+A_ji=2Q_ij`. The frozen models' SHA256 agrees with the plaintext validation and both final aggregate artifacts. Therefore using the Q-based reference in this particular harness does not conceal a changed original network.

The real-product theorem in `algebra.md:7-17` is also valid in its stated homogeneous-real cost model: the common kernel of the first factors is totally isotropic, so intersection with positive/negative definite subspaces forces k>=max(p,m); spectral opposite-sign pairing attains it. This is not a lower bound on SIMD ciphertext multiplications. The packed method already performs one ciphertext multiplication in both arms.

## Findings and repair obligations

1. **The benchmark portfolio is narrower than its own strong-comparator plan.** `packed.go:182-190` compares only symmetric and cyclic-oriented contraction, each with direct/official-BSGS ratios 0 and 1. `prior_art.md:49-58` additionally calls for an optimized original packed square network, simple triangular symmetry elimination, spectral signed squares, real product factors, and best feasible layouts. The available LDL/spectral factors are plaintext artifacts, not executed competitors. These omissions do not invalidate this ablation; they block claims such as "fastest quadratic FHE method", a general compiler advance, or superiority beyond this kernel family. In particular, terminal complex signed-square packing is a plausible competing representation and has not been timed here.

2. **Three listed backend settings are not exhaustive tuning, and some are duplicates.** Final artifacts show the two symmetric BSGS ratios lower to the same N1 for d=8,16,32; candidate ratios also coincide for d=8,32. Official `FindBestBSGSRatio` searches powers of two and ratios above 1 can exchange more cheap hoisted baby rotations for fewer expensive giant steps. Lattigo itself documents this time/key tradeoff in `circuits/common/lintrans/lintrans.go:74-79,320-340`. Sweep distinct legal splits or restrict the claim to the three tested settings. Also distinguish `algebra.md:107-109`'s arbitrary-integer baby length bound from the executed official schedule: at d=16, oriented k=9 permits b=3 and four mathematical BSGS rotations, while the artifacts execute power-of-two splits requiring five. The stored operation counts reflect the executed five, which is correct.

3. **Output acceptance is recorded but not enforced by the executable.** `packed.go:357-371` accumulates max absolute/imaginary errors but contains no rejection for real error>1e-3 or nonfinite decoded outputs. A future failing run could exit successfully and write ordinary results. Require a post-run acceptance check or a clearly separate verifier before declaring a run valid. At this audit snapshot all 84 final method/model/ring records have finite reported maxima and nine complete-chain samples; all pass the declared threshold. Worst real error is `3.176100221935485e-6` in Standard and `1.054975123793156e-5` in CI. Thus this is a robustness/interpretation gap, not an observed accuracy failure.

4. **Encrypted error assurance is empirical and the effective input count is limited.** Per dimension the harness uses one deterministic B=128 input fixture with five special patterns and 123 random dyadic examples, reused under fresh encryption in nine repetitions (`packed.go:130-168,317-323`). Separate model seeds are present, but same-dimension models share the same input seed. Checking all replicated output lanes is good and can expose lane faults, but repeated lanes/re-encryptions are not independent draws from the application input distribution. The all-corner and 1000-random-point validation in `model_validation.json` is explicitly plaintext only. Additional held-out encrypted input sets, more corner/coordinate/cancellation cases, and fresh independent keys would broaden evidence. No domain-wide CKKS error theorem follows from these tests; the protocol correctly disclaims one.

5. **Final security documentation is inconsistent with the executed parameters.** `security.md:15-30,38` still analyzes Standard Q bit sizes [50,40,40], P=[50], nominal logQP=180 and about 2^10 final headroom. Executable/protocol use [58,40,40], P=[60], logQP about 198 and about 2^18 headroom, with a second CI ring arm (`packed.go:90-96`). The Standard final parameters remain below the published Category-128 uniform-ternary dimension-8192 QP bound 214, so the larger modulus does not by itself refute the table-based assessment. This must be stated for the actual configuration, rather than inherit the obsolete 180-bit assessment. CI has a different ring and sampler geometry; the audit has not independently reconstructed the mapping to the table's LWE model. Provide the applicable real-subfield security argument or estimator setup before calling that arm independently security-certified. This is an assurance gap, not evidence that CI is insecure. Across ring arms the generated prime arrays differ (2N versus 4N root requirement); "matched Q/P" means matched bit sizes, not identical prime values. Within each arm every method shares the exact same parameters.

6. **The measured speedup is not uniform, and fixed ordering limits causal precision.** Methods run in one fixed order (`packed.go:186-190,204`), with one client keypair per model/ring and fresh method-specific evaluation keys. Warmup is separate, which is appropriate, but cache/thermal/GC effects can correlate with method position. Nine sequential samples are not nine independent full experiments. At audit time the best-median complete-chain symmetric/oriented ratio is 0.992 for CI archive8h64 and 0.991 for CI heldout_d16h96seed20261024: the candidate is slightly slower there. Standard ratios range about 1.077-1.459; CI ratios about 0.991-1.363. These are descriptive medians from the available run, not confidence bounds. Preserve regressions and obtain fresh counterbalanced or interleaved confirmation before asserting stable small percentage gains. Best settings should be selected on tuning runs and assessed on reserved runs to avoid best-of-noisy-settings bias.

7. **Resource telemetry is explicitly incomplete until fresh-process RSS/setup evidence is added.** `packed.go:205-213,408-410` records Go HeapAlloc at stage boundaries, not peak resident memory; it misses transient peaks, stack/native allocations and allocator-retained pages. Model, keys, serialized keys, deserialized server keys and the client key can coexist in one process, so that RSS represents this simulated protocol deployment rather than an isolated server's resident set. Do not present heap snapshots as peak memory or server-only memory. `/usr/bin/time -l` with one selected method per fresh process is the appropriate separate evidence; protocol already requires it. Full reported one-time setup must also identify what is common/offline: the timed preparation starts from already collapsed Q; network-to-Q expansion, frozen JSON load and input-fixture generation are outside these timers. The former cancels for symmetric/oriented ablation, but not automatically for an original-network comparison. All relevant model encoding, key generation/codec and warmup costs are separately present. Actual network latency is unmeasured and disclosed; key and ciphertext byte counts are real. Any amortization claim must use those one-time costs and a stated network model.

## Checks that passed

- The only decryptor is client-side (`packed.go:181,351`); the evaluator's signature and operations are secret-free (`packed.go:54-74`). Re-encryption of intermediates does not occur.
- Client packing is a coordinate layout/periodic replication, with encoding and fresh public-key encryption timed. It does not compute Ax or factors in plaintext for the server.
- Complete local chain timing covers pack/encode, encrypt, input binary codec, actual homomorphic evaluation, output binary codec and final decrypt/decode (`packed.go:318-353`). Plaintext verification and evidence disk writes are outside timing and disclosed. No uncharged server-side layout conversion appears in this fixed-layout kernel.
- Same original model, B=128, fixtures, one thread, parameter object, permitted error and executable are used per symmetric/oriented comparison. CI's additional physical slots contain periodic copies, not secretly doubled application batches.
- Lattigo v6.2.0 is pinned in go.mod. Key/encryption randomness is internal to Lattigo; math/rand is used only for public benchmark fixtures. No sparse-secret override or bootstrap appears.
- One ciphertext multiplication/relinearization, two rescales, log2(d) reduction rotations and no bootstraps match the visible execution. Diagonal multiplications and direct/BSGS rotation counts in the final artifacts agree with the checked kernels. Counts are statically reconstructed from the schedule, not instrumented hardware counters.
- `compiler_ldl.py` verifies exact rational LDL reconstruction and gives exact rational residual certificates for stored floats. Its zero-diagonal Schur-block spectral fallback is explicitly labeled uncertified inertia; it does not silently certify floating spectral signs. The packed runtime does not rely on this factor compiler.

### Remaining substantive boundaries

No unresolved implementation blocker was identified for the stated restricted experiment after the verified repairs. The following constraints remain part of any defensible report:

1. **Distinguish steady-state chains, setup and deployment.** HTTP key distribution is measured, including server key deserialization/installation. Its roundtrip must not be added to `key_deserialize_seconds` again. HTTP setup, public model encoding, key generation/serialization, public-key costs and warmup are separately logged. Loopback TCP does not measure WAN latency, bandwidth or TLS. Public model data is prepared at the server before inference; it is not secretly delivered as transformed client input.
2. **Do not call these timers a complete source-model compilation total.** Frozen network-to-Q expansion and stored LDL/spectral decomposition were generated before these Go timers. For the main symmetric/triangular/oriented comparison, the Q collapse is common and cancels; the orientation's A construction/encoding is timed. For comparison with original networks or affine factors, a complete lifecycle total must additionally state/include the applicable offline expansion/factorization costs from the frozen model metadata. The factor certificate's runtime is measured separately and should be identifiable as certification work, not mandatory query computation. Setup crossover claims are valid only for the listed components and deployment horizon.
3. **Keep assurance levels separate.** The exact coefficient identities/certificates are global over their stated box. CKKS acceptance is empirical. Published security tables and the documented CI assumption are not a newly proved cryptosystem. Sampling, shared keys and deterministic fixtures do not support unstated confidence claims.
4. **Keep scope and negative results visible.** The confirmation models are the three selected synthetic dimensions, not fresh confirmation of every held-out model, every ring or every baseline family over HTTP. Other arms have their nine-repeat sweep evidence. Extra parameter/layout optimizations and a trained-model task are not covered. Priority remains qualified; it is independent of whether this implementation works.

The current verification report pins checked source/artifact hashes and the current executable hash. ## Third audit: separate server address space, 19 October 2026

The final strengthening adds a real exec child for protocol-isolation validation. I inspected `bench/server_process.go`, the refactored transport, the first branch in main, and the new packed-mode branch. Read-only evidence checks are saved in `artifacts/independent_isolation_audit.json`. No extra benchmark was run by the auditor.

**Isolation verdict: established for the inspected child entry path and smoke evidence.** `main.go:14` calls `MaybeRunServerProcess()` before flag parsing, model-file loading, input fixtures, key generation or client cryptographic object construction. When invoked with the sole argument `--fhe-server-process`, that function decodes public configuration, creates a public-model encoder/server, announces readiness and blocks indefinitely (`server_process.go:88-153`). It cannot return to ordinary client initialization. No main-package init function generates a key. Although the parent has created its own key before it launches the server, exec starts the child in a distinct address space; the child does not inherit the parent's Go heap or key objects.

The exec arguments contain only the executable path and mode flag. The explicitly supplied environment is exactly `GOMAXPROCS=1`, with no inherited client credential environment. Stdin is an anonymous pipe whose schema contains serialized public CKKS parameters, real/imaginary public matrix and affine coefficients, a public constant, layout, BSGS choice and square-kernel flag (`server_process.go:24-35,69-85,156-171`). Those values are derived solely from the public model/parameters. There are no input vectors, secret keys, decryptors, plaintext references or acceptance results in that schema. Serialized CKKS parameters describe distributions/moduli and are not a serialized secret key. Unknown JSON fields are rejected.

The child rebuilds its own encoded public transform and starts the same secret-free HTTP handler. `/keys` receives a serialized public evaluation-key set and `/infer` receives and returns ciphertexts. The handler contains no key generation, decryption, client fixture access or callback into client code. The ready record checks that the announced PID equals the actual exec child PID and differs from the client PID, and that its public-config hash matches the sent pipe content. This is process address-space separation, not a claim against a compromised OS, administrator/debugger access or deliberately published synthetic benchmark fixtures.

The key-installation response, warmup and all three inference responses identify PID20415. Child exit peak RSS is **49,479,680 bytes**, above its recorded in-query peaks. No parameter or output-tolerance downgrade was introduced.

The child is stopped and waited for before final result serialization, so its own `RUSAGE` peak is attached to that validation result. Startup wall time already contains JSON serialization, exec/pipe transfer, child public encoding and listener readiness; its subcomponents must not be summed again. Parent model preparation and child encoding both occur in this protocol variant, so lifecycle accounting must retain the distinction.

The earlier 45-process confirmation dataset still measures a fresh **combined client/server process per plan**, with an HTTP server inside that process. Its latency and RSS evidence must remain labeled accordingly. It must not be called isolated-client RSS or a simultaneous sum of parent and child RSS. The manifest's `resource_scope` label, confirmation script and README have now been corrected and independently rechecked for that interpretation; none of the following comparisons uses that ambiguous OS value. The verification report pins the final records hash after this clerical correction.
