# Independent prior-art and contribution review

Date: 2026-10-19. Scope: exact scalar-output, public-weight, one-hidden-layer square-activation networks, and ciphertext-aware evaluation of their fused quadratic polynomial. This note reviews sources and proposes comparison obligations; it does not report an encrypted reproduction or establish priority.

## Supported assessment

The strongest defensible candidate contribution is a **consumer-aware quadratic execution rule**: optimize a matrix representative of a scalar quadratic polynomial for the encrypted layout and kernel, rather than insist on preserving the intermediate vector of the original network or the symmetric matrix-vector product. The proposed cyclic-orientation rule is a concrete instance. A second candidate is terminal real-part semantics for signed-square evaluation with complex CKKS slots. Both require measured comparisons, and their historical novelty remains unestablished.

The original real product-count result is an algebraic statement, not a ciphertext lower bound. For `f(x)=sum_j w_j(a_j^T x+b_j)^2+c`, public preprocessing yields `Q=A^T diag(w) A`, `l=2A^T diag(w)b`, and `c0=c+b^T diag(w)b`. A scalar arithmetic circuit minimizing products of real linear forms can have different cost from packed CKKS: many independent scalar products can share one ciphertext multiplication, while their linear maps can require different rotations and plaintext products. This is a deduction from the execution model, not a reproduced benchmark.

## The precise cyclic-orientation comparison

Let slots repeat a block of `d` real inputs. Define `(R_r x)_i=x_(i+r mod d)`, and suppose the scalar sink is `sum_i x_i (Mx)_i`. Its value depends only on `(M+M^T)/2`. Thus `M=Q+K` for any real skew-symmetric `K` represents the same scalar quadratic as symmetric `Q`. Such a change is illegal for a generic matvec consumer and legal for this particular reduction consumer.

For each non-self-inverse offset pair `{r,d-r}`, combine its contributions into one direction. If `D_r[i]=Q[i,i+r]`, symmetry gives `D_(d-r)[i+r]=D_r[i]`; the scalar contributions of the two offsets agree after index renaming. Keep `2D_r` and remove `D_(d-r)`. Keep the zero diagonal unchanged. If `d` is even, `r=d/2` is self-inverse and its existing diagonal contribution is kept unchanged. This leaves at most `floor(d/2)+1` nonzero cyclic diagonals, including the zero diagonal, instead of `d`. A single direct kernel can compute

`u = l + sum_(r in chosen offsets) E_r * R_r(x)`,

`f = sum_slots(x*u) + c0`.

The improvement is a reduction of plaintext diagonal products and eligible direct rotations, with the same single ciphertext multiplication. It is not a new diagonal matvec algorithm. The new candidate mechanism is changing `M` within the scalar-equivalence class *before* applying that algorithm. A dense instance requires at least one active diagonal for every non-self-inverse offset pair in this restricted representation: two zero partner diagonals would force the corresponding symmetric coefficients to vanish. This is a restricted support bound, not a global FHE operation lower bound.

BSGS can make fewer rotations than a direct diagonal implementation even without orientation. Therefore compare the oriented and symmetric matrices under the same best available linear-transform backend, sweep legal BSGS splits, and count plaintext products independently. Also compare their level and scale schedules: doubling retained coefficients can increase dynamic range and error. The rule must earn its overall advantage under fixed output accuracy, and can lose on sparse or unusually structured inputs.

Focused primary-source searches did not locate a paper explicitly stating this scalar-consumer cyclic-folding rule. This records the scope of the completed search, not a priority proof. Generic facts `x^T Kx=0` and `x^T Qx=x^T upper(Q)x` after doubling off-diagonals are elementary and must not be presented as new mathematical discoveries.

## Terminal complex semantics comparison

For real linear forms `u,v`, `Re((u+iv)^2)=u^2-v^2`. An indefinite signed-square decomposition can therefore pair a positive and negative square in one complex linear image, and use the real part of the final decrypted result. No server conjugation is required when no later operation needs the discarded imaginary channel. For a positive pair, `Re((u+iv)*conj(u+iv))=u^2+v^2`, but encrypted conjugation adds an evaluation key and key switch unless the representation provides another construction.

This is an algebraic observation using standard complex CKKS semantics, not a novelty claim. It should be evaluated against real signed-square SIMD, real bilinear pairing, and direct `Q` kernels. Full complex ring and conjugate-invariant real ring have different slot capacities; using different rings without accounting for effective batching would be an unfair comparison. The client must encrypt the same public layout of input coordinates for all compared methods; model-dependent plaintext feature extraction at the client would move inference work outside the server timing.

## Required strong baseline portfolio

1. **Original packed network:** optimized public-weight rectangular matvec, SIMD square activation, then optimized weighted scalar reduction. If 64 hidden coordinates fit in a ciphertext, all 64 squares can share one ciphertext multiplication. Include kernel setup, plaintext encodings and layout conversions.
2. **Fused symmetric quadratic:** evaluate `sum(x*(Qx+l))+c0` with optimized diagonal and BSGS kernels and hoisting. This is the critical graph-fusion ablation.
3. **Simple triangular quadratic:** upper-triangular representative, off-diagonals doubled. This tests whether cyclic orientation improves beyond ordinary symmetry elimination.
4. **Spectral signed squares:** transform by `diag(sqrt(abs(lambda))) V^T`, square, signed-reduce; share SIMD operations and fold public signs into a legal schedule.
5. **Real product-minimal factorization:** the `max(p,m)` route, with both linear maps fully costed; product count alone is not the metric.
6. **Best layout available to each:** coordinate-block packing, feature/batch packing if practical, and comparable BSGS choices. The final reported baseline is the fastest valid member under identical application/security/accuracy requirements, not the most convenient implementation.

Use the same cryptographic parameter set initially for mechanism isolation. A second experiment may independently right-size each method, but must preserve the same security assessment and output error threshold. Report both comparisons. Add a fallback selector choosing the baseline when a candidate's predicted total cost is worse, and validate selection on reserved models rather than retuning thresholds on final inputs.

## Contribution claim ladder and remaining obligations

- **Established mathematical facts:** network-to-quadratic fusion; skew-symmetric freedom; elementary real/complex identities. Their correctness can be proved without FHE but does not demonstrate efficiency.
- **Candidate reusable construction:** select a scalar-equivalent matrix using diagonal support, BSGS cost, key union and error constraints, then lower it with an existing FHE backend. Specify the optimization variables and cost function; a measured choice among ad hoc cases alone is weaker evidence.
- **Possible empirical contribution after execution:** a reproducible restricted-class improvement over the fastest optimized baseline, with security, error, setup and packing held fixed and multiple predetermined instances. Name the measured regime rather than claiming universal acceleration.
- **Outstanding historical originality:** no absence-of-hits argument establishes novelty. Compare the exact rule with FHE quadratic kernels, consumer-aware algebraic compiler rewrites, synthesis/vectorization, and matrix-representation optimization. Consider expert review before a paper-level first/new claim.

The independent reviewer should reject: hidden client feature transforms; client-assisted nonlinearities; excluding model encodings, key distribution or conversions; comparing SIMD against scalar ciphertext execution; changing ring type/effective batch without adjustment; an output-error failure concealed by averaging; and savings that disappear after key/setup amortization. Once measurements exist, this note should be supplemented by an explicit before/after operation schedule and an ablation showing exactly which proposed rule causes the gain.
